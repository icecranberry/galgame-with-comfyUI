# 小镇互动与店铺

建筑与 NPC 的功能权限只保留两项，生成时写入 `capabilities`，落库为 `capabilities_json`：`["service"]` 为服务类，可提供服务并创建特殊奇遇；`["trade"]` 为交易类，打开交易窗口买卖道具；`["service","trade"]` 同时拥有两项。普通对话继续可用。未知类型、空数组被拒绝，损坏的存档权限不会自动放行。

蓝图的 `buildings.businessKind` 只描述具体内容用途，如服装店、理发店，不是额外功能分类；`npcs.workplaceKey` 指向工作地点。建筑素材、地图与 NPC 建档均保存权限，双方权限可以独立配置。生成清单、居民管理详情、地图地点编辑共用两项选择器。已有明确配置不会因为改名或修改职业而被覆盖，自动补岗的居民默认继承工作地点功能。

必要的补给站、工坊及员工在生成清单中补齐，员工与普通居民一起生成完整人格和形象。已注册营业用途每种一处，住宅和景观的内容用途使用 `none`。即使建筑名称没有对应的营业用途，声明交易功能也会在生成名单中配置商贩。

地图、NPC 先后生成都可以；双方落库后统一补齐经营关系、有限启动资金、库存、道具模板和生产资源，不必到钱袋手工开张。开镇在这一步完成后才进入可游玩状态。加载旧镇时按建筑用途、岗位和职业补齐；缺少基础场所时在广场附近增加可达的公共补给摊、手作摊，不挪用私人住宅或特色地标。缺失人员明确显示待到岗，后续创建 NPC / 保存地图会重试。

已经配置的经营关系优先保留，重复生成、加载和追加店铺不会重发启动资金。已经手动关闭经济的镇不会因读取而重新开启。钱袋用于查看资产和补充额外岗位。经营者在营业时间加入工作模拟，入住角色仍遵循自己的原有日程。

| 入口 | 实际行为 |
| --- | --- |
| 服装店 | 现货购买、定制、帮工；回收本店衣物 |
| 理发店 | 付费确认波波头造型，完成后领取发型卡 |
| 按摩店 | 付费确认舒缓护理，完成后领取元气护理券 |
| 普通居民 | 默认服务类：闲聊、托付、特殊奇遇；额外配置交易后可买卖 |
| 聊天邀请 | 查看详情，再选择接受或婉拒；接受才执行交易或导航 |
| 剧情线索 | 服务类 NPC 或建筑邀请已有正式角色参与，使用原有奇遇生成、分支与结局系统 |

服装、发型和护理效果沿用现有背包系统：完成服务获得道具，在背包为角色使用。服务取消全额退款；完成后钱款进入店铺账户，回收也从同一账户支出。店铺销售必须走店内库存与服务结算，不能从经营者的通用货摊绕过库存。

点建筑先到门口，再显示其功能入口；旧地图中原先没有地点的普通建筑会补上独立地址，重复加载不复制地址。交易窗口包含店内现货与回收，点击店内商品继续原有报价和取货流程。服务入口可选择已有业务或展开特殊奇遇。后台在目录、确认与剧情保存阶段检查权限，交易类不能通过伪造邀请创建奇遇；建筑和其经营者的邀请也不能串用。

NPC 的具体内容按职业分配，已配置店铺目录优先，再按两项权限过滤。原有 `functions_json` 是内部内容声明，不作为额外功能分类。模型只选择服务端目录的 key，不决定价格、奖励或道具内容。无模型时，固定交易和服务按钮仍可使用。

`town_interaction_offers` 保存邀请、来源 `source_key`、确认结果和剧情关联。相同来源的同类邀请当天重复询问会恢复原请求；尚未接受的目录内容改变后可重新报价，生成中或已结算的请求不覆盖。商人的常规买卖可重复交易，每笔使用独立幂等键；断线重试恢复同一笔交易。邀请保留30分钟；剧情生成最多占用20分钟，超时可重新读取。不同世界、建筑或居民的邀请不能串用，交易与邀请确认同一事务提交。

剧情奇遇继续显示在原有奇遇页，小镇可以直接进入对应事件，事件列表和历史保留线索来源及回镇入口。已有活跃剧情优先继续。原引擎仍需要正式角色档案，但角色可作为来访者参与，无须提前入住，不改变居住设置，也不把轻量 NPC 自动转成正式角色。所有角色均关闭奇遇时显示明确提示。剧情文字不直接增减钱物，真实后果由小镇账本、道具和任务结算确认。

扩展建筑时更新 `townVenuePlaybooks.js` 的目录、服务键及前端命令白名单，并为建筑增加本地奇遇。新增模型输出字段必须同步完整JSON示例和解析。验证包括端到端的赚钱、消费、回收、退款、邀请恢复与剧情关联，以及重复确认、过期、归属和世界隔离测试。
