# 邻舍本地补丁 · 总设计案

> 本文件是「邻舍」本地补丁项目的**范围权威**。它只定义**这一轮要做什么、分母是什么**；
> 事实与证据、以及"从哪里继续"写在 `docs/NEXT.md`。两者之间的结构化块由 TavernWeave
> 进度画板读取并投影到 `progress/`。

## 一、这个项目是什么

「邻舍」是一款本地运行的 AI 角色聊天应用。本项目**不是**重写它，而是**在上游之上维护一套本地改动**：

- 上游以 tag 持续发版，本地改动全部提交在 `local` 分支，更新时把 `local` rebase 到新 tag 上重放。
- 因此本地改动**天然免疫版本更新**（`checkout --force` 只丢工作区、丢不掉提交）。
- 上游的东西能不改就不改；必须改时集中在少数文件，便于日后 rebase 冲突定位。

范围依据（可核对的来源）：

| 来源 | 位置 | 作用 |
|---|---|---|
| 本地补丁清单 | `邻舍-local/项目地图.md` | 按主题分组的补丁全景与完整清单 |
| 操作宪法 | `邻舍-local/AGENTS.md` | 规则优先级、边界、写回门禁、提交与验证约定 |
| 提交历史 | `git log v3.6.3..local` | 每个改动的真实内容 |
| 自动检查记录 | `docs/验证记录/` | 可引用的检查留痕 |
| 项目记忆 | `.workbuddy/memory/` | 当日工作日志与长期项目约定 |

## 二、目标与取舍

**目标**：让"本地改动"这件事本身可被检查 —— 每个事项说得清做了什么、证据在哪、还差哪道验收。

**取舍**：

1. **范围只收"正在推进且可核对"的事项**，不把 39 个历史补丁全列进来充当分母。
   历史补丁的价值在于"为什么这么改"，已在 `项目地图.md` 里；看板不需要复述。
2. **不迁移上游文档格式**。上游 `docs/` 下已有 5 份方案与 1 份进度文档，本项目沿用它们，
   只把与本轮相关的部分收进下面的范围块。
3. **证据只认项目内路径**。数据类改动落在 `agent-core/data/`（gitignore），
   无法作为文件证据，改用 `.workbuddy/memory/` 的留痕，并在检查点说明里注明这一限制。

## 三、验收门怎么算

| 门 | 含义 | 本项目怎么取得 |
|---|---|---|
| `automated` | 自动检查 | 跑 `agent-core` 的服务层检查/测试套件，结果留痕到 `docs/验证记录/` |
| `browser` | 浏览器验收 | 无头浏览器实开界面核对渲染与交互 |
| `real-host` | 真实宿主 | 本项目为本地应用，一般用不到 |
| `driver` | 驾驶员验收 | **由使用者确认"这就是我要的效果"**，须登记确认依据 |

**注意**：检查点标 `implemented` 只说明**代码/文件确实存在**，不等于验收通过。
百分比在范围被确认（`baseline.confirmed = true`）之前不显示。
