# 神说工具补齐与确认修复

2026-11-05。本文记录[修复前验收报告](./验收报告.md)之后的实现。测试业务数据均为独立内存库或明确的测试临时库；没有向真实业务数据库执行操作。未添加任何小镇工具，未提交 commit，保留工作区内其他任务的改动。

## 直接执行

已补齐指定工具并修复原报告中的八类问题。工具总数为 **101**：18 个核心工具、83 个模块工具。完整目录与确认分类见 [tools-after.csv](./tools-after.csv)。

### 新增工具

| 工具 | 行为与边界 |
| --- | --- |
| `initialize_emoji_prompts` | 指定角色与套装，调用原表情生成器初始化全部类别；首次新增直接保存，覆盖已有提示词先展示完整草稿 |
| `generate_emoji_images` | 根据已有提示词批量生成，默认只补缺图；明确覆盖时先出候选图，确认后采用已经展示的图片，不再次生成 |
| `read_emoji_set` | 读取套装的每条提示词、图片和生成状态，核验后台任务，而非仅返回“已受理” |
| `read_angel` | 读取天使独立档案与四套服装，不使用普通角色编号 |
| `update_angel` | 按字段修改天使名字或人设，改名无需携带整个人设，确认后生效 |
| `apply_angel_appearance` | 生成天使默认外观的完整替换稿；只改默认外观段，确认后提交 |
| `generate_angel_outfits` | 复用原服装生成规则设计/修改天使私服、居家服、睡衣，确认后只保存选中槽位，不自动绘制形象 |

表情包已经验证完整流程：新建空套装 → 初始化提示词 → 批量补图 → 查询逐项状态 → 重做某张图片 → 查看原图/候选图 → 确认采用同一张候选图。跨角色套装编号会被拒绝。

### 原有工具修改

| 修复前问题 | 现在的行为 |
| --- | --- |
| 修改已有数据绕过确认 | 角色/天使资料、外观切换、日程修改与重排、道具收取/消耗、叫醒、临时变身、收藏等由后端生成确认卡 |
| 纯新增也确认 | 新建角色、群聊、关系、独立外观、世界观、媒体及内容不再额外确认；内部任务状态更新不单独确认 |
| 改名预览漏掉名称 | 卡片明确展示新旧名字；只提交修改字段；旧版未展示新名字的待确认草稿拒绝提交 |
| 改名强制复制完整人设 | `update_character` 支持只传 `character_id + display_name`，普通角色接口按已有原文更新派生摘要，保留原人物卡 |
| 专属外观由天使自由编写 | 设计要求使用 `instruction`，走原外观扩写接口；`description` 只能原样使用本轮用户提供的正文，不能用模型编出的描述绕过生成器 |
| 外观输出格式约束不足 | 拒绝 JSON、代码围栏及一至六级 Markdown 标题，继续只替换共享人格组装器定位到的外观正文 |
| 重生成时边确认边改写 | 日程、已有日记正文、表情提示词先准备完整草稿；确认后提交冻结内容，不重新调用文字生成器 |
| 世界事件的新增参数修改旧事件 | 带 `supersedes_id` 时必须确认，展示将结束的旧事件与新增事实，检查旧事件快照 |
| 后台受理被当作完成 | 保留受理/未启动/部分完成等真实返回；确认卡的后台任务显示“已提交”，提示查询实际结果 |

确认分类看用户可见的业务副作用，不只看 SQL INSERT/UPDATE。例如新建独立禁用外观直接保存；临时变身会停用旧形态，所以需要确认；创建世界事件如果结束旧事件，也需要确认。

场景服装写入已有角色/天使衣柜仍需确认，即使目标槽位此前为空。表情包空套装的首次内容初始化、缺少图片的首次生成属于新增内容，直接执行。

### 能力缺失必须停止

- 已知未接入的实体诉求在调用模型之前拒绝：小镇店铺改名、删除角色、已有图片放大等。
- 小镇只是普通图片/朋友圈的地点时仍允许，不把地点词等同于小镇管理功能。
- 未知工具或能力目录返回“该模块未接入”时，立即停止当前批次中剩余调用，并直接说明边界；不给模型继续改用世界事件、发帖或改人设的机会。
- 世界事件只设定叙事事实，不能当作修改店铺名称、删除角色或修改系统设置的接口。
- 受阻回合仍保存完整的工具请求/结果配对和已发送提示词快照，后续会话可正常续接。

已知缺失诉求的前置识别采用明确规则，不能据此声称对任意自然语言措辞都有数学保证。未知工具/未知模块的停止是执行层约束；今后出现新的表达方式或新的能力缺口，应补充对应边界回归。

### 一致性与并发保护

提交前重新检查原数据，生成期间或等待确认时发生修改则拒绝覆盖。确认守卫已移到所有业务路由之前；异步生成后的实际落库位置也重新核验。表情图片生成期间被上传/替换的新图不会被旧任务覆盖。

已确认的日记不再次生成正文；日记后台运行期间若原内容/角色被修改，不覆盖新内容。已有日记任务还在运行时，提交另一份确认稿返回冲突，不能把未提交伪装成成功。日程确认稿同样拒绝与正在运行的相关日程生成任务争写。

天使档案写入仍复用原独立存储。集成测试对比普通 `characters` 表前后内容，验证天使改名、默认外观和睡衣修改没有改动普通角色。

UI 没有引入新皮肤。图片对比复用 `GodMessageImages`、只读 `ImageLightbox`、已有响应式布局、主题 token 与 300ms 过渡；通过前端逻辑测试、ESLint 和生产构建。本轮未另外保存浏览器截图。
