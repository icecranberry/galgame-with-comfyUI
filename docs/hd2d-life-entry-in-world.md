# 生活入口回到世界里：钱袋 / 公告站 / 进店

2026-09-10。用户要求“开启各种任务不该是把入口放在生活按钮里面，应该放在特定的建筑里或者 NPC 里”。本轮把原来的「生活」按钮拆开：顶栏只留钱袋子，公共委托与备料回到公告站，打工、点单、投宿、学艺一律到对应建筑或掌柜本人那里办。

## 改前的问题

- 顶栏一个「生活」按钮里同时塞了钱包、公共基金、开张向导、配送三站、工坊备料、配送委托、回访预约，以及酒馆/裁缝铺的进店入口。玩家在哪儿都能办事，世界里的建筑与掌柜反而没有意义。
- 面板要认识每座建筑的名字和字段，新增一座建筑就要改面板；咖啡馆、酒馆、裁缝铺各有一份入口逻辑。
- 服务端其实一直要求“人到店、店在营业”，但面板可以在世界任何角落打开，报价与接受经常要在最后一刻才被 `NOT_ARRIVED` 拒绝。

## 现在的分工

| 入口 | 位置 | 内容 |
| --- | --- | --- |
| 钱袋 | 顶栏按钮（原「生活」） | 钱包、公共基金、首次开张向导；已开镇只提示“镇上的事，到地方办” |
| 公告站 | 点地图上的公告站建筑 | 配送三站、工坊备料、配送委托、回访预约 |
| 功能建筑 | 点建筑本体或该店的经营者 | 当班、帮工换物、点单、定做、投宿、学艺等本店玩法 |

规则：

1. **公告站例外，其他都要到店。** 公告站是公共窗口，点一下立即打开；其余建筑与掌柜都先走人过去，进店条件与服务端 `townService.hasArrived` 同口径（不在移动中且切比雪夫距离 ≤ 地点 `radius`），到店才开面板。
2. **经营者本人也是门。** 点建筑或点掌柜走同一条路：`enterWorldSpot` → 需要就先 `walkToSpot` → 到了再 `openSpotPanel`；面板里保留「先和XX聊两句」，聊天记录仍归原私聊管线。
3. **前端不认名字。** 热区完全由 `/api/town/economy` 的投影生成：`slice.locationKeys.board`（公告站）、`economy.service`（工坊）、`economy.cafe`（咖啡馆）、`economy.venues[]`（注册表建筑）。新增建筑只改 `townVenuePlaybooks.js` 的 `VENUE_KINDS`，前端不再加分支。
4. **到地方才报价。** 面板里的报价、接受与阶段推进仍由服务端结算；“走到了吗”不再是最后一步才发现的问题。

## 验收

```powershell
# 工作目录：web-ui
node test/town-view-browser.mjs          # 建筑点击 → 公告站 / 酒馆面板、三个视口、触摸与卸载
node test/town-life-browser.mjs          # 钱袋与公告站分屏、幂等重试、取消与退款、键盘焦点
node test/town-character-browser.mjs     # 掌柜忙碌时仍可进店，且不影响角色对话
```

- `town-view-browser` 用等距投影算出建筑屏幕位置并真的点画布：公告站立即开、酒馆先看是否在半径内、面板关闭后回到世界，全程只有显式出行才发一个 `player/move`。
- `town-life-browser` 证明两个面板同屏只开一个、切面板不影响待确认操作，控件被移除后焦点仍在弹窗内（Escape 与 Tab 循环由暖纸外壳统一处理）。

## 边界与未做

- 世界生成尚未自动为每座建筑布点；哪些建筑开张仍由开张向导显式选择（留空即不开）。
- 没有室内场景与寻路进门的过场动画，走到地点半径内即视为到店。
- 公告站之外的公共信息（例如镇公共基金流水）仍只在钱袋面板里，不随建筑分发。
