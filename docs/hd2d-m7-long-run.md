## 实际执行方式与预算

fixture沿用 `townProductionRuntime` / `townLiquidityRuntime` 的正式初始化和命令路径，参考 `townRecoveryMatrix` 的暂停/恢复顺序及 `townCrossDomainAudit` 的账本校验。

- 导入 runtime 前设置 `DB_PATH=:memory:`，并断言 `db.name === ':memory:'`；正式迁移和业务 setup 创建初始资金/库存/有限节点。没有通过测试转账、补库存、补proof或每日seed维持经营。
- 实际调用 `town.movePlayerTo`，按返回 `pathLength / playerSpeed` 推进虚拟时间，并检查真实位置已到达；没有注入 `hasArrived=true`。NPC初始位置/固定作息属于fixture输入，后续工作和证明由实际 `forceTick`、action runner及production runtime产生。
- 使用 `Date.now` 虚拟时钟及Node MockTimers；不推进自动timer，而明确驱动runtime tick。因此不真实等待90天，也不会混入墙钟scheduler拍数。
- `townLLM=false`，所有fetch被本地拦截：兼容现有模块的 `/object_info` 发现请求，只返回空对象；其他请求记录并抛错。没有实际HTTP、模型、图片生成或真实库访问。回放没有浏览器/性能采样。
- 正常路径每个日期最多3次配送→30元服务；每次服务后最多20个一分钟tick等待补货。其后跳到当天19:00收盘进行维护。每个日期的固定观察预算不等同全天连续在线。
- 囤币路径每天最多一次配送，不消费。两路径各跑90个日期并在30/90日留快照，再分别用全新内存库重放一次，比较**所有每日聚合、失败统计和路径计时**完全一致。UUID/事件ID本身不要求逐字节一致。

90天双路径各两遍共约106秒墙钟；另一个30/90天恢复测试约0.9秒（含启动）。只执行这些新测试，没有扩跑主线套件。明细见 [results.json](../output/hd2d-m7-long-run/results.json) 和 [recovery.json](../output/hd2d-m7-long-run/recovery.json)。

周转是明确的采样代理值，不是全天库存积分。囤币路径停业后平均库存继续降低，会使该比率反而上升，不能据此评价经营改善；工坊正常路径日末为0但已满足当天消费，也不能当作每天断货。库存实物流更直接：正常90日 `20初始+200补货−216配送=4`，工坊 `216收货−216消费=0`；囤币工坊积压20。

runtime没有“破产/违约清算”状态，所以JSON的 `bankruptcyCount=null`，不能将非负余额或零余额次数冒充居民/商家破产验收。公共基金保留60也不表示能随时发布任务：冷却已经阻止27次需求。

实际路径计算的**成功配送移动分钟毛收入**：正常6480 / 54.133分钟 =119.704币/分钟；囤币600 / 5.2分钟 =115.385币/分钟。只包含成功单的真实寻路时长，排除失败尝试、生产等待、用户阅读/操作、网络/模型时间；它是fixture机械基线，**不是玩家真实每分钟收入**。

正常216次成功发布时玩家都是0元，从当时位置到公告站并接下无垫资单为0–8000ms；囤币仅第一单是0元，起点就在公告站，耗时0。该指标只统计成功样本，冷却/缺货造成的长期无法接单时间未纳入，不能据此声称贫困玩家总能8秒找到工作。完整等待时间分布仍未覆盖。

## 长期离线与错误时钟增补

分别从独立内存库，通过真实命令完成一单服务，留下其生产预算30和节点1预留，再完成第二笔配送、接受第二次付费服务并确认材料。停止Town scheduler，跳到30/90天后19:00收盘时刻，再启动并执行维护；不是关闭并重开SQLite文件，内存连接保留。

- 单纯时间前跳不增加任何经济交易。
- 维护后生产过期、预算/节点预留释放，proof仍0、节点仍200；不会补出离线工作或工资。
- 已扣材料的服务按原TIME_LIMIT规则过期：退20、支付10，只结算一次，不新增完成道具。
- 重复维护后交易数量及完整观测快照不变；累计策略发行0，没有补发30/90天额度。
- 在这份真实持久policy state上回拨到起始时间之前，新发布被 `LIQUIDITY_CLOCK_ROLLBACK` 拒绝；恢复时间后资金/库存观测不变。

这是支付/生产组合的长期runtime恢复增补。实际SQLite关库重开、预约路程/租约恢复仍由现有 `townRecoveryMatrix` 覆盖，本轮没有把内存连接上的重启称为磁盘重启。
