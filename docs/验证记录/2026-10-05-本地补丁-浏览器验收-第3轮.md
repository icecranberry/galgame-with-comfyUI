## 本轮修复（逐条对应驾驶员报告）

### ① 出刊按钮与期号导航「没有真实出现」（根因：ReferenceError）

`web-ui/src/views/MediaView.vue` 的 `reloadIssues()` 里引用了**已经不存在的标识符**
`activeIsPortal`（重命名为 `activeIsPeriodical` 时漏改了这一处）。

关键区别：它不是「条件恒假」那么温和 —— 引用未定义标识符会**抛 ReferenceError**，
而抛出点又在 `try` 之外，于是：

1. `reloadIssues()` 每次都以 rejected 结束 → 期简目恒为空 → 期号导航整块不渲染；
2. `onMounted` 里 `await reloadIssues()` 之后的所有语句被跳过：`loading=false` 没执行
   （页面永远显示「加载中…」）、首屏补图没跑、SSE 订阅没挂上。

- PASS 数字报刊/顶栏：选中刊物后主按钮变为「出刊」　— 按钮文案=出刊；refresh-group 未渲染
- PASS 数字报刊/期号导航：期简目取到并渲染　— chips=[最新1 期, 第 1 期（1/5）]
- PASS 数字报刊/首屏：不再卡在「加载中…」　— `.media-loading` 未渲染

### ② 滚到最下端，滑块不动（根因：末尾章节比视口短）

`MediaPortal.vue` 的 `onScroll()` 只用 `offsetTop <= scrollTop + 8` 判定。
某章要被点亮，必须满足「章节顶边在内容里的位置 <= 当前 scrollTop」；
滚到底时 `scrollTop = 内容高 − 视口高`，于是**只有比视口还高的章节才可能被点亮**。
末尾章节（榜单/跟帖区）往往恰恰是最短的那块 → 一路滚到底，滑块卡在倒数第二章。

修法：滚到底（留 2px 容差）直接点亮最后一章 —— 滚到底本身就代表"看到最后一块了"。

- PASS 门户/滚动联动：滚到底后高亮落在**最后一章**　— 章节=5 个；activeIndex=4/4；activeText=跟帖区：狸友深夜刷屏
- PASS 门户/滚动联动：滚动到底的判定成立　— scrollTop=1795 / maxScroll=1795 / atBottom=true

### ③ 左侧竖排章节字号偏小

`.po-nav-item` 字号 12.5px → **14.5px**，行高与内边距同步放宽；
栏宽 208px → **238px**（只放大字号会把中文标题全挤成两行小字，反而更局促）。
窄屏横排时回收到 13.5px。

- PASS 门户/左栏排版：字号已放大　— computed font-size=14.5px
- PASS 门户/左栏排版：栏宽已同步放大　— flex-basis=238px

### ④ 《狸狸通讯社》内容错误进入「官方传媒」（根因：分类白名单漏 print）

`routes/media.js` 的分类白名单曾硬编码 `=== 'digital' || === 'social'`，
新增的 `print` 落进 else → category 变成 `null` → **变成"不过滤"** → 门户帖整批混进该档。
改为读 `services/mediaService.js` 导出的 `MEDIA_CATEGORIES`。

顺带发现并修掉同一类的第二处：后端的 `digital` 仍写着
`o.layout IN ('weekly','poster','portal')`，与前端 `isDigitalOutlet`（只认 portal）不一致
→ **同一张海报会同时出现在「数字报刊」和「官方传媒」两档**。
现在两侧都改为读 `CATEGORY_LAYOUTS` 这一张映射表（print=poster/weekly、digital=portal、social=feed/NULL）。

- PASS 官方传媒/分类：不再出现狸狸任何内容　— outlet 标签=[📰邻舍日报, 全部0]；special-wrap 数=0
- PASS 官方传媒/分类：该档计数为 0（门户帖未被算入）　— 分类标：📰官方传媒 0
- PASS 数字报刊/分类：《狸狸通讯社》《狸狸八卦》都在这一档　— outlet 标签=[全部2, 📰狸狸通讯社 刊1, 📸狸狸八卦 刊1]

### ⑤ 「报纸物料」改名为「官方传媒」

分类 key 仍是 `print`（前后端共用的契约，改 key 不划算），只改界面文案与注释。

- PASS 分类标：文案已是「官方传媒」　— 三档：📰官方传媒 0 / 📸数字报刊 2 / 💬社交平台 0

### ⑥ 额外修掉两处「点了没反应」（本轮排查中发现，非驾驶员报告）

「全部」档点刷新时，后端 `generateMediaBatch` 是**全局** `ORDER BY RANDOM() LIMIT 1` ——
站在「数字报刊」可能抽到社交平台的媒体，生成的内容不出现在当前分类里，
用户看到的是"没反应"，而 token 已经烧掉了。现在刷新带上分类，只在分类内抽。
同一档若一个媒体都没有，按钮直接禁用并给出正确引导（原来会静默空转）。

- PASS 官方传媒/空状态：文案指向"去加媒体"而不是"去刷新"　— 「还没有官方传媒物料」+ 引导到媒体设置
- PASS 官方传媒/刷新：无媒体时按钮禁用并说明原因　— disabled=true；title=这个分类下还没有媒体，先去右上角「媒体设置」新建一个
