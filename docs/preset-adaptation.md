# SillyTavern 预设适配

入口在酒馆：关系图占整行，下一行是世界观和 SillyTavern 预设。管理窗口复用 LinsheModal、Linshe 表单控件；桌面左侧列表贯穿正文全高，管理操作与紧凑名称配置移至右侧，编辑 / 预览使用 md 页签且保留列表；窄屏上下排布。弹窗开关和内容切换使用 0.3 秒过渡。

## 请求结构

预设按具体业务请求显式接入，默认不注入。`llm/llm-client.js` 只负责发送；`services/lorebook/runtime.js` 只负责世界书，两者都不读取预设。不能在通用客户端、世界书适配器或按请求标签猜测的拦截器里加预设。

正文请求在组装处选用 `services/presets/narrative.js`：简单请求显式调用 `chatWithPreset(messages, opts)`；需要规划、流式回复、补充记忆或延迟提交的请求调用 `prepareNarrativePrompt(originalMessages, lorebookOptions)`，再把 `prepared.messages` 交给原客户端。共用的只有编译和插入机制，是否接入由每个业务调用点决定。混合用途文件必须同时保留普通客户端，不能整体替换为预设客户端。

| 接入预设的正文 | 不接入预设的辅助请求 |
|---|---|
| 私聊主回复、群聊、主动聊天、醒来回复、延迟回复、事件招呼 | 深度思考规划、记忆提取/整理/浓缩、预测、情绪分析、关系提取、群名生成 |
| 朋友圈正文与评论、赴约朋友圈、梦境与梦话、日记、回信、日报 | 图片识别、生图助手、配图提示词、画风测试、立绘与触摸台词、表情包、角色反应包、头像/背景设计 |
| 奇遇生成/分支/结局、镇民奇遇与朋友圈、NPC 对话、居民偶遇对话、礼物与 NPC 服务叙事 | 小镇地图/建筑/素材、NPC 档案/日程/服务配置/库存、状态气泡、偶遇摘要、物品配置、素材库生成 |
| 媒体周刊、帖子、栏目正文 | 媒体海报设计、门户栏目骨架、媒体档案与头像设计、信箱浓缩、日程规划 |

按内容用途判断，不按返回格式判断：奇遇或朋友圈的 JSON 包含正文，仍接入；结构规划、图片参数等 JSON 不接入。新增请求默认沿用普通客户端，确实需要文风才显式选择上述正文入口。

接入后的请求结构：

```
原第一个 system（system0）
预设独立 system（有生效正文才添加）
原有其他 system / 历史 / 附件
原本的最后 user
```

未启用、空预设、全部停用、只有变量赋值或标记的预设不产生空消息。没有 system 的正文请求将预设放在消息开头；不伪造基础规则或额外 user/assistant。不覆盖原提示词，不移动附件，不拆解历史外壳。正文入口可显式传 `preset:false`；普通客户端无需传这个选项，本来就不会注入。

正文组装器先编译一次预设，将 token 预算经 `reservedTokens` 留给世界书，再让世界书基于原消息解析锚点，最后插入预设。原调用方的 `cacheBoundary`、历史与人设偏移无需手工加一。世界书本身不读取、保存或绑定预设；一次正文生成通过闭包复用已编译正文，`reapply` 先从未注入消息重新排版世界书，再放回同一份预设。世界书报告的 index/offset 继续指原消息位置；最终请求中首个 system 后的索引会增加一。

私聊的 Planner 使用 `prepared.lorebookMessages`（有世界书、无预设）；主回复使用 `prepared.messages`。生图助手独立使用原世界书客户端，不从正文请求继承预设。

服务商重试、免费模型轮换和回退复用已经展开的消息，不重复执行变量或随机宏。固定预设、固定宏输入的正文逐字稳定；含用户名、角色、当前输入、日期、随机或未知宏的预设**不被声明为静态内容**。用户选择的位置固定在 system0 后，这些动态内容会使后续前缀缓存随调用变化，预览明确提示。

## 兼容范围

| 能力 | 实际行为 |
|---|---|
| 导入 | 聊天补全 JSON（`prompts` + `prompt_order`），以及 Prompt Manager 的 `data` 包装与扁平排序导出 |
| 配置保留 | 除下述已移除的注入控制字段外，未识别的顶层、条目、扩展、采样字段原样保存和导出；不将 ST 模型、温度和输出额度覆盖到邻舍 |
| 排序 | 优先全局 100001，否则首个排序；窗口可选其他原始排序配置，不将 ST 角色 ID 当作邻舍角色 ID |
| 启用 | `prompt_order[].order` 的开关为准；不在所选排序中的条目默认不执行，窗口可加入；列表原顺序决定宏执行与正文拼接顺序 |
| 位置与角色 | 原 role 仅保留数据用于导出，不显示或参与运行；injection_position/depth/order 与 forbid_overrides 导入时移除。实际全部映射为 system0 后同一 system |
| 生成类型 | `injection_trigger` 导入时移除；只在显式接入的正文请求中按条目开关执行，不由 ST 生成类型决定业务接入范围。旧预设读取、预览和编译也剔除上述五个字段，避免隐藏配置继续生效；原导入文件不修改 |
| 内容标记 | charDescription / charPersonality / personaDescription / worldInfoBefore / worldInfoAfter / scenario / dialogueExamples / chatHistory / agentSystemPrompt / agentTask / agentResults 由邻舍原流程提供，不重复注入；开关不控制邻舍原有内容 |
| 变量 | setvar / addvar / getvar / incvar / decvar；支持嵌套，变量按本次请求共享，不读取或写入其他会话及 ST 的持久变量；addvar 支持数值累加、字符串拼接和 JSON 数组追加 |
| 其他宏 | 注释、trim、newline、noop、char/user/description/personality/persona/scenario、lastUserMessage/lastCharMessage/lastMessage、date/time/weekday、random/pick；pick 在邻舍按当次请求抽取，日期不支持 ST 格式扩展 |
| 不执行 | ST 全局变量、扩展 JavaScript / STscript、扩展正则、助手预填充；未知宏保留原文并报告，不执行任意代码 |

预设变量不是世界书变量，两个引擎各自隔离。预览与请求共用 `compilePreset`；切换到预览即自动展开当前草稿，只展示将注入 system1 的正文；条目开关或排序变化自动刷新，过期响应不回填。默认使用当前用户称呼和人格，不伪造当前输入；未指定的角色/历史按模拟上下文处理，动态宏实际随业务请求变化，状态提示可查看。界面不再要求填写表单或二次点击，不展示通用消息骨架及逐条报告。预设本身可能约定其他输出格式，仍由用户选择适用于邻舍任务的条目。

## 保存与验证

SQLite `prompt_presets` 保存适配后的文档、选定排序、名称、激活状态和版本；唯一索引保证同时最多一个激活预设。保存、激活和删除检查 revision，旧窗口收到 409 后须重新载入。导入或复制先形成草稿，保存后手动启用；切换预设保留各自草稿，关闭或重新载入会提示未保存修改。

限制为 4 MiB 文档、2000 个提示词、32 层嵌套宏、30000 次展开操作、单段/变量 2 MiB，以及累计展开上限。超限报错，不截断后发送残缺提示词。

正式测试：`agent-core/test/promptPresets.test.js`、`agent-core/test/llmOutputTokens.test.js`。覆盖导入导出保留、排序/开关、嵌套变量、标记/废弃字段清理、限制、空注入、附件/历史不变、快照、CRUD/并发，以及捕获真实 SDK 的同步/流式/重试 HTTP 请求体（原 `presetScopes.test.js` 与 `web-ui/test/promptPresets.test.js` 已随 2026-11-06 测试精简移除，需要时从 git 历史取回）。

## 神说的严格追加模式

神说显式使用 `presetPlacement: 'cache'`，其他正文请求仍沿用上面的默认位置。编译保持原条目和变量执行顺序，仅将输出分成两段：首个动态或未知宏之前的固定前段放在 system0 后；从首个动态宏开始的整个输出后缀放在本轮 user 前的 system。动态变量赋值即使没有正文也会划定后缀，后续变量引用、固定文字不再搬回前方；日期、随机、当前消息、未知或未闭合宏均不认证为稳定。宏只编译一次，重试使用同一结果。

神说在 `god_prompt_prefixes` 保存会话首轮前缀，在 `god_prompt_turns` 按 user 消息保存最终请求片段（包括动态预设 system、世界书、日期和图片）。后续加载原生历史时用已存片段替换对应 user，原文仍供界面、摘要和关键词扫描使用。旧版消息没有请求快照时沿用原文，不伪造过去的日期或附件上下文；新发送的回合开始严格追加。跨日沿用原会话前缀，手动新建和重新召唤的新会话重新建立前缀，删除回合级联删除对应快照。

同一天固定规则或预设发生显式修改，以本轮尾部 system 更新生效；停用预设也以尾部说明生效，不覆盖之前已经发送的 system 或 user。稳定世界书已注入的内容随历史保留，后续不重复插入，条件条目和新增内容只能注入当前 user。每轮发送前校验已保存前缀逐条一致，不一致则终止该请求，不静默覆盖快照。保证的是本地消息前缀一致，不等于提供商已回报的缓存命中率。
日程按仍在历史中的实际已发送片段去重，每日会话首轮注入一次；只有内容或启用状态变化才追加带替代说明的更新。兼容没有日程元数据的旧文本/图片快照，删除携带日程的回合后自动补入必要版本；不修改已发送快照，也不会继续新增旧版的重复日程。每轮使用“本条用户消息发送时间”标记 run.created_at，固定规则解释旧时间的历史属性；不再把每条历史都称为“当前日期时间”。
